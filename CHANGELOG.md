# Changelog

## 1.1.0 — 2026-10-19 (공개 준비, 영어 UI, 맥 앱)

### Added
- **`portboard.json`, the site config** ([docs/config.md](docs/config.md)). This server's details used to be literals in the code: its name, the tailnet, the checkout path, the repos root, the compute-pool URL, the pve1 and Windows SSH defaults, and the public connector URL. Now they come from one optional file, `~/.config/portboard/portboard.json` (`PORTBOARD_SITE`), so Portboard can run on another Linux host without code edits (#37). Each value resolves on its own:
  - The existing environment variables come first (`PORTBOARD_POOL_URL`, `PORTBOARD_REPOS_ROOT`, `PORTBOARD_DASHBOARD_URL`).
  - Then what the machine reports: `tailscale status` for the host and tailnet, git for the checkout, the OS user, and `tailscale serve status` for the dashboard URL.
  - Then the file, then the old value as the default, so with no file production behaves as before.
  - A preview gets its own copy of the file, like `prefs.json`. `pveports.json` and `winports.json` still win over the file's `pve` and `windows` defaults.
- The 설정 tab's 정보 section shows this server: its name and MagicDNS name, checkout, repos roots, compute-pool URL and the config file's state, each with where it came from. `GET /api/settings` adds `site`.
- **커넥터 상태 on the 설정 tab** (REA top-10 #10): each remote MCP client and authorization shows its last use and a badge: 정상, 만료 임박 (the authorization ends within `soonDays`), 응답 없음 (live tokens, but no call for `idleDays`) or 만료됨 (a registered client whose tokens are gone). A banner "연결 n개가 확인이 필요해요" offers 다시 연결, with the steps and 승인 코드 만들기 inline, and "n일 동안 숨기기", which is per browser and returns early when something new needs a look. `GET /api/remote/clients` adds `health`, `attention` and `thresholds`. The thresholds are set in `remote.json` `"health"` and default to 7/7/7 days. The setup checklist's claude.ai 커넥터 item warns, and the digest adds one 🔌 line, only when a connection needs attention (docs/settings).
- **Resizable sidebar and inspector** (docs/layout): drag a pane's inner edge (3 px before it counts) to set the sidebar to 200–420 px and the inspector to 280–480 px. Drag the sidebar under 100 px and it collapses; a click on its edge toggles it. The handles are keyboard separators (← →, Home / End, Enter). The widths are remembered in `pb.shell` and applied before the first paint. The list keeps at least 324 px, so wider panes move the breakpoints up: at both widest, the sidebar is a column from 752 px and the inspector from 1232 px. At the default widths the layout is unchanged.
- **One shortcut registry and a ⌘/ 키보드 단축키 dialog**: `public/lib/keys.js` defines every shortcut once (⌘K, /, ⌘\, Esc, ↑/↓, ⌘/, 뒤로/앞으로), and the same entries drive the key handlers, the palette's 명령 rows (now showing their keys) and the dialog. Keys read as ⌘ glyphs on a Mac and in the Mac app, and as Ctrl words elsewhere. In the Mac app the dialog also lists the app's own menu keys (⌘1–4, ⌘[, ⌘R, ⇧⌘O); a test keeps the page's shortcuts off them.
- Portboard for Mac (`mac-app/`, [docs/mac-app/](docs/mac-app/README.md)): a native SwiftUI app, the successor of the SwiftBar plugin.
  - The dashboard in a window with native tabs (서비스 · 기기 · 개발 · 설정), 뒤로, 새로고침 and 브라우저에서 열기. Links that leave the dashboard open in the default browser, and the window size and position are remembered.
  - A menu bar item: `⇄ n` services in use, `↓` watched ports down, `⚠` devices to check, `🧹` cleanup candidates. The menu has services in use, pinned ports, devices, local-only services with tailnet 공개, and leftover servers.
  - macOS notifications when a watched port or device goes down or comes back, and when a new device appears. Deduped across restarts; off by default when ntfy already sends them.
  - Settings: server URL with 연결 확인 (`/api/whoami`), notification toggles, poll interval, 로그인할 때 열기.
  - Unreachable server (Tailscale off) is said in plain Korean with 다시 시도, never a blank page.
  - Built on the Mac with `mac-app/build.sh` (Swift package, Command Line Tools, ad-hoc signed; `--install` copies it to /Applications). The pure logic has XCTest tests on the plugin's fixtures (`swift test`, also in the Swift docker image on Linux).
- `/api/health?detail` runtime: `heapUsedMb`, `heapTotalMb`, `externalMb` and `arrayBuffersMb` next to `rssMb`. RSS stays high for minutes after a scan's garbage is collected; `heapUsedMb` is what is actually live.
- **메모리 on the 기기 tab** ([docs/memory](docs/memory/README.md)): under 이 서버, a bar of used / cache / free with swap, PSI and the hour's sparklines, then where the RAM goes. Claude sessions are listed with their whole process tree, title or project, CLI version (구버전 when older than the newest running), 쉰 시간 and 쉬는 중. MCP servers are summed across sessions with their instance count (세션마다 실행 marks a user-scope server). Services and dev servers, docker (from cgroups, no `docker stats`) and the rest follow. The groups are a strict partition, so every process counts once. One 60 s job on the shared scheduler reads `/proc` directly, about 150 ms for 600 processes. `GET /api/memory`, and the local-only MCP tool `memory_usage`.
- **Suggestions, no actions**: idle sessions to archive in the Claude app (쉬는 세션 N개가 X GB), sessions on a stale CLI, MCP servers that run in every session but were rarely called in the last 7 days (the transcript scan now counts calls per MCP server), and long-idle dev servers with a link to the 서비스 tab's 정리.
- **Memory-pressure alerts** through the down alerts' channel: available under 10 %, PSI `some avg60` over 5 or swap over 90 % for 5 minutes sends one warning, a reminder every 6 h while it lasts, and one recovery once it is clear with a margin. Thresholds are in `memory.json` in the config dir; state survives restarts. While it is on, the sidebar's 수집 chip shows 메모리 부족. The digest gets one 🧠 line, and `portboard://status` (local and remote) gets a numbers-only `memory` line.

- **Port rules** ([docs/config.md](docs/config.md#port-rules)), after VS Code's `remote.portsAttributes`. Labels, pins, hiding and new-port notices can now be set for many ports at once in `prefs.json` `portRules`. A key is a range (`18891-18899`), a `host:port` matched against the bind address (`localhost:5173`, `*:3000`), or a case-insensitive regex on the owning command line (`vite|next dev`). `otherPorts` applies to ports that no rule matches.
  - The port's own entry (a rename, pin or hide on the dashboard) always wins. Then come host:port, the narrowest range, and regexes in file order. Each field comes from the first source that sets it. With rules present, an unpin or un-hide is stored, so the rule doesn't pin or hide the port again.
  - Edit them on the 설정 tab's new **포트 규칙** section, with `GET`/`POST /api/port-rules`, or with the local MCP tools `list_port_rules` and `set_port_rule`. A single-port key is written as that port's own entry, like a rename. Invalid keys and rules are ignored and listed.
  - The 서비스 inspector's **규칙** section shows which rules matched, in order, and where the name and the new-port setting came from. `GET /api/ports` entries add `onNew` and `rules: {matched, from}`.

  - `openBrowserOnce` shows only the toast with 열기.
  - `silent` (the default for everything else) and `ignore` (which also hides the port) show nothing.
  - The server looks every 15 s and debounces per port and command for 10 minutes. It never notifies for what was already listening when it started, for its own ports, or for a port in a restart/stop quiet window. The push only goes out where alerts are on.
  - Events are served at `GET /api/new-ports?since=<id>` for the dashboard and, later, the Mac app ([docs/api.md](docs/api.md#new-ports)).

The error screen says "자동으로 다시 시도하는 중…" with the next try's time and keeps 다시 시도. A crashed page process is reloaded at most 3 times in 5 minutes. Rebuild the app (`mac-app/build.sh --install`).

### Changed
- The setup checklist's commands use the resolved values instead of literals: `claude plugin marketplace add <checkout>`, the Mac app's `rsync <user>@<host>.<tailnet>:…` and `cpool agent --coordinator <host>`. MCP tool descriptions, the remote server's instructions and the pve reader's labels take the host and node from the file or the defaults. `src/core/site.ts` is the only place in `src/` that names the production host.
- The rest of the devbox literals outside `src/` (#37). The web app manifest says "Listening ports on this server", the 기기 tab's subnet-router hint falls back to "이 서버" when there is no self card, and the Claude Code plugin's `dev-servers-and-ports` skill says "this server".

The commands in docs/mcp.md, docs/setup.md and docs/menubar/ pass the target. See [docs/config.md](docs/config.md#outside-src).

### Security
- `remote.json` lock: two waiters that both find a stale lock (left by a crashed writer) can no longer both take it. They race for an `O_EXCL` marker named after that lock file, and only the winner removes the lock, after checking it is still the same file. A holder's release no longer removes a lock someone else holds (#7).
- Approval codes: the per-address limit on wrong tries counts an IPv6 client by its /64, the 20-try budget from all addresses together stays the bound, and the try that burns a code is logged as `approval-burned`. A hand-edited `failures` value that isn't a number no longer keeps a code alive forever (#7).
- Loopback redirects (`http://127.0.0.1:*`, `http://localhost:*`) with `allowLoopbackRedirects` unset, including when there is no `remote.json`, are accepted only from loopback and the tailnet, never through Funnel. `true` still allows them on the public URL, and `false` still refuses them everywhere. Local setups (Claude Code against `127.0.0.1:8794`, the smoke script before going public) work as before (#7).
- CIMD `client_id`s must be canonical https URLs with no `?` or `#` at all. An empty query or fragment, dot segments, an upper-case host or a spelled-out `:443` are refused before any fetch (#7).
- `GET /api/audit` is the owner's only: a process on this machine, or the owner's login through `tailscale serve`. Other tailnet callers get `403 owner only`, and the dashboard's 최근 기록 and the service page's 기록 say only the owner can see them. Every other read stays open to the tailnet (#7).
- Read-only mode (`PORTBOARD_READ_ONLY=1`, on by default in the Docker image): every write route answers `403 {"error": "read-only"}` before its handler (audited as denied), restart, stop and dev servers are refused in the core as well so MCP tools and the session-end auto-stop can't get around it, and `canRestart` / `canStop` are `false` (#11).
- `requireTokenOnLoopback` (or `PORTBOARD_REQUIRE_TOKEN_ON_LOOPBACK=1`) makes local processes, and `tailscale serve` logins that arrive over loopback, send the owner token too: the opt-in fix for "loopback has no token" in `docs/security.md`. The default is unchanged (#12).
- In token mode Funnel never gets write access, token or not, and a wrong, malformed or uncheckable token takes write rights away, even on loopback. The token is compared in constant time and never written to a log, URL or the audit log (#12).

Another user, a tagged device, Funnel and any direct connection to `http://<host>:8790` get `403 {error: "owner only", reason}` before the body is read; reads are unchanged. Decisions are a pure function with a table of tests (`src/core/access.ts`), wired in one place (`appRouter`).
- No token, token hash, family or client_id leaves `remote.json` through the dashboard: the list uses derived `c-…`/`g-…` ids, and tests scan every response (#31).
- Write devices (security review v1.0, M1): serve and direct callers are identified as a tailnet node with `tailscale whois` (X-Forwarded-For on the serve path, the socket for direct; cached per address, never a shell). Every audit line and `GET /api/whoami` carry the device (`{addr, name, id}`). An optional allowlist, `writeDevices` in `~/.config/portboard/access.json` (0600, `PORTBOARD_ACCESS` moves it) plus `PORTBOARD_WRITE_DEVICES`, limits serve writes to the listed node names or stable IDs; other owner-login devices get 403 with a Korean reason naming the device, and a broken or loose file fails closed. Unset, nothing changes, but the 설정 체크리스트 warns "쓰기 가능한 기기 제한 안 됨" and lists the owner-login devices that can write.
- Audit log can't be flushed by denials (M2): denied requests go to their own capped `audit-denied.jsonl`, and identical ones (who, source, route, reason, device) are coalesced to about one line a minute with a `count`. 7,000 denied POSTs now leave the earlier writes in `audit.jsonl`.
- Every dashboard answer sends `X-Frame-Options: DENY`, `Content-Security-Policy: frame-ancestors 'none'`, `X-Content-Type-Options: nosniff` and `Referrer-Policy: no-referrer` (L3).
- `X-Real-IP`, `Via`, `True-Client-IP`, `CF-Connecting-IP` and similar headers count as proxy markers, so a local reverse proxy that sets only one of them no longer makes its clients the owner (L5).
- State and config files are written 0600 through random, `O_EXCL` temp names; `deploy/portboard.service` gets `UMask=0077` and `NoNewPrivileges=yes` (L6). The installed unit must be copied by hand (`scripts/deploy.sh` doesn't install unit files).
- 500 answers carry a generic Korean message and a request id instead of the error text; the error is logged under that id, and the audit line no longer holds it.
- The dashboard server gets `headersTimeout`/`requestTimeout`/`keepAliveTimeout` and a 256-connection cap per listener, like the remote server.
- Heavy reads any tailnet device can trigger are bounded (v1.0 security review L1): the port snapshot, topology and usage are computed one at a time and shared, and `?fresh` skips their 2 s cache at most once per 5 s; a forced full worktree scan is accepted at most once per 60 s and a forced transcript scan once per 10 min (sooner, the running or latest result with a note, never an error); `GET /api/ports/:port/logs` resolves the owner from the shared 2 s snapshot; `GET /api/claude/port-advice` takes free ports from that snapshot (no `ss` / `tailscale serve status` per request), caches reservations for 2 s and the cwd's `repo@branch` for 10 s per cwd (bounded, one git call per cwd at a time).
- The port-nudge text no longer carries untrusted text as-is (L4): HTTP titles, session titles, reservation notes and owners, process, unit and container names and branch names are cleaned of ANSI escapes, control and format characters (zero-width, bidi overrides) and newlines, capped at 60 characters and quoted, and a line after the `[portboard]` marker tells the model quoted text is data, not instructions. A path a suggested tool call needs is quoted unchanged, or left out when it holds such characters.
- `git status` in scanned worktrees and in listening processes' checkouts, `git worktree remove`, and the port-advice cwd lookup run with `-c core.fsmonitor=false -c core.hooksPath=/dev/null`, so a checkout's config can't make `portboard.service` run a program (I4).
- The dev-server script allowlist checks own keys (`Object.hasOwn`), so `constructor`, `toString` or `__proto__` never pass it (I2).
- `readOnlyCore` is typed `Required<Core>` and names every Core method, optional ones too (`setAlert`, `alerts`, `newDevices`, `collection`, `serviceDetail` added as not remote); a test checks that every method but the three remote reads refuses (I1).
- CI: the workflow's token is `contents: read`, and `actions/checkout` and `actions/setup-node` are pinned by commit SHA (I10).

### 기기 tab
- **새 기기 (new device) alert** (#10): Portboard keeps a record of known devices in `known-devices.json`, keyed by Tailscale name, MAC or IP. On the first run it seeds that record from what is visible (tailnet peers, LAN cards, the neighbour table, the last-used history), so nothing alerts on day one. After that, a device that connects to a service here for the first time gets a 새 기기 badge, shows up in a 새 기기 list at the top of the tab, and is announced once through the down-alert channel. At most one message goes out per 10 minutes; anything that comes up inside that window goes into the next message. Each entry has 이름 붙이기 (LAN devices) and 확인; naming a device also clears its badge. New MACs in the neighbour table (ARP) can alert too, but that is off by default. Settings live in `prefs.json` → `newDevices`.
- **Proxmox CPU/memory trends** (#11): CPU and memory sparklines for the last hour on the pve1 card and on guest cards, and a CPU sparkline on each guest row in the VM/CT list. Tapping one opens a 24 h chart (10-minute averages, tap or hover for a value) in the detail panel. Guests without a card of their own (jellyfin) get a detail of their own. The data is Proxmox's own RRD data read with the existing PVEAuditor token, cached 60 s.

### Data
- **LAN names**: `ip neigh` gives the MAC address, the IEEE OUI list gives the vendor, and the user can name a device (`clients.json`). Same-machine detection compares SSH host keys.

- **Proxmox** (read-only token, pinned TLS fingerprint): the host and VM/CT tree. Guests are matched to devices by MAC, name or IP.
- **compute-pool**: host status from `GET /api/hosts`, and the other hosts' listening ports (desktop over ssh; the Mac once its worker is updated).
- **Last-used history** in `~/.local/state/portboard/usage-history.json`, with 30-day retention.

### Alerts
- Down/up alerts for ports you choose (🔔) and for tailnet devices, sent through compute-pool's ntfy/webhook channel. They are debounced and rate-limited, and suppressed after a stop or restart you made in Portboard.

- **Remote, read-only** (`src/remote.ts`): Streamable HTTP with OAuth 2.1 + PKCE and a one-time approval code. It allows only read tools and redacts its output (no IPs, MACs, paths or commands). It is public through Tailscale Funnel on :8443.

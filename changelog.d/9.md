### Added
- The `portboard` command (`bin/portboard`, `src/cli.ts`): `portboard start` (the dashboard), `portboard remote [approve|status|revoke]` (the remote MCP server), `portboard mcp` (the stdio MCP server), `--version`, `--help`. It runs the same from a checkout and from an npm install (#9).
- `portboard install-service [--remote] [--enable] [--dry-run]` writes `~/.config/systemd/user/portboard.service` (and `portboard-remote.service`) for the node running it and the install it runs from, instead of `deploy/*.service`'s hard-coded nvm path and checkout, with the same hardening (`UMask=0077`, `NoNewPrivileges=yes`, `Restart=always`). It prints the `systemctl --user daemon-reload && enable --now` line, or runs it with `--enable`. `portboard uninstall-service` disables and removes only the units it wrote (#9).
- The npm package: `npx portboard start`, or `npm i -g portboard && portboard install-service`. Node won't strip types under `node_modules`, so the tarball carries `src/` compiled to `dist/` (`npm run build`, run by `prepack`, `tsconfig.build.json`); a checkout still runs the `.ts` files directly (#9).
- `.github/workflows/release.yml`: a `v*` tag checks the version, runs the typecheck and tests, packs and smoke-tests the tarball, publishes to npm with provenance (`NPM_TOKEN`) and creates the GitHub Release from the CHANGELOG section (`node scripts/changelog.ts --notes <version>`). A Developer ID signed and notarized Mac app job runs only when the six `APPLE_*` secrets are set, and is skipped otherwise (#9).
- The memory view recognizes `portboard mcp` (and `npx portboard mcp`) as Portboard's MCP server (#9).

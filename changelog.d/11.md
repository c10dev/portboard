### Added
- **macOS**: the server and the agent run on a Mac. Listening ports come from `lsof -nP +c 0 -iTCP -sTCP:LISTEN -F pcnL` and owners' command lines and folders from one `ps` and one `lsof` per snapshot; stopping a port's process works as on Linux, and a plain process's logs are found through `lsof` when it writes to a file. Restart of units, dev servers and the memory view answer with the reason (`501` for `/api/memory` and dev server starts) instead of failing, and the memory job doesn't run without `/proc` (#11).
- `portboard install-service` on macOS writes launchd agents to `~/Library/LaunchAgents` (`io.github.c10dev.portboard`, `-remote`, `-agent`) with output in `~/Library/Logs/portboard/`; `--enable` loads them with `launchctl bootstrap gui/<uid>`, `--dry-run` prints them, and `uninstall-service` boots out and removes only the plists it wrote. Other non-Linux systems get a clear refusal (#11).
- **Docker image** (`Dockerfile`, `.dockerignore`): `node:22-bookworm-slim` with `iproute2`, non-root, `HOME=/data` as a volume. Run with `--network host --pid host --user "$(id -u):$(id -g)"` it shows the host's ports read-only (#11).
- A platform layer (`src/core/platform/`): the port reader (`ss` | `lsof`), the service manager (`systemd` | `none`) and read-only mode are chosen from the OS, with `PORTBOARD_PORT_READER`, `PORTBOARD_SERVICES`, `PORTBOARD_READ_ONLY` and `PORTBOARD_CONTAINER` to override. Off Linux the server logs one line saying what it uses and what it can't do; a plain Linux install behaves and logs exactly as before (#11).

### Security
- Read-only mode (`PORTBOARD_READ_ONLY=1`, on by default in the Docker image): every write route answers `403 {"error": "read-only"}` before its handler (audited as denied), restart, stop and dev servers are refused in the core as well so MCP tools and the session-end auto-stop can't get around it, and `canRestart` / `canStop` are `false` (#11).

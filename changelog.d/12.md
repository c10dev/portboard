### Added
- Token mode for installs without Tailscale: with `"mode": "token"` in `access.json` (or `PORTBOARD_ACCESS_MODE=token`), a request carrying `Authorization: Bearer <owner token>` may write from loopback, the LAN or the tailnet, recorded in the audit log as source `token`. `portboard token` makes the token (32 random bytes), prints it once and keeps only its sha256 in `owner-token.json` (0600); running it again rotates it. Settings › Display › Owner token keeps it in the browser and the dashboard sends it as a header (#12).
- `PORTBOARD_ALLOWED_HOSTS` adds names (e.g. `devbox.lan`) to the dashboard's `Host` check for a LAN bind, and a wildcard bind (`0.0.0.0`) allows this machine's own interface addresses. `/api/whoami` says `mode: "token"` and `tailscale: false` when they apply (#12).
- Without Tailscale, expose/unexpose and the write-device allowlist answer `409` with a clear message, and Settings leaves out the write-enabled devices section (#12).

### Security
- `requireTokenOnLoopback` (or `PORTBOARD_REQUIRE_TOKEN_ON_LOOPBACK=1`) makes local processes, and `tailscale serve` logins that arrive over loopback, send the owner token too: the opt-in fix for "loopback has no token" in `docs/security.md`. The default is unchanged (#12).
- In token mode Funnel never gets write access, token or not, and a wrong, malformed or uncheckable token takes write rights away, even on loopback. The token is compared in constant time and never written to a log, URL or the audit log (#12).
